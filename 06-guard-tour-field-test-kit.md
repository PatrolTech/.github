# A 15-minute guard tour field test

A practical exercise for security supervisors evaluating patrol recording workflows. Published by **PatrolTech / Ingenieros Web SL, Madrid**.

## Before starting

Use an authorised demo device and sample records. Keep the exercise separate from live safety procedures. This is a proposed evaluation exercise, not a certification or a report of a completed product test.

## Minutes 0–3: the test route

Choose two test checkpoints. Assign an operator and a reviewer. Write down the expected visit sequence, the device used and which records you expect to receive.

Use the [daily activity report template](https://securityguardtour.com/templates/daily-activity-report?utm_source=github&utm_medium=referral&utm_campaign=field_resources_2026&utm_content=kit_daily_report) to organise observations alongside the patrol record.

## Minutes 3–7: recording without connectivity

Enable airplane mode on the authorised test device. Record a visit and a sample incident. Note what the app says about locally saved or pending records. The exact offline procedure depends on the product configuration; record what you observe.

## Minutes 7–11: reconciliation

Reconnect using an approved connection. Compare the expected visits with the records received. Distinguish the time a visit occurred from the time the record arrived. Observe missing entries, ordinary retry behaviour and any work still pending.

Mark each item as **observed**, **not observable** or **needs follow-up**. A missing result is a finding to investigate, not a reason to fill in an assumed outcome.

| Check | Evidence to keep | Your observation |
| --- | --- | --- |
| Visit and arrival times | The two timestamps and their definitions | |
| Delivery | Expected visits compared with records received | |
| Ordinary retry | Whether a retry produces a second record | |
| Incident context | Checkpoint, note and attachment visible to the reviewer | |
| Pending work | Any unsent record and the status shown to the operator | |

Translate important findings into purchasing questions with the [guard tour software RFP template](https://securityguardtour.com/templates/rfp?utm_source=github&utm_medium=referral&utm_campaign=field_resources_2026&utm_content=kit_rfp).

## Minutes 11–15: incident handover

Ask a second person to reconstruct the event from the record. Keep observations separate from actions. Identify the next owner, the next step and what still needs confirmation.

Use the [incident report template](https://securityguardtour.com/templates/incident-report?utm_source=github&utm_medium=referral&utm_campaign=field_resources_2026&utm_content=kit_incident_report) for a structured handover. Treat sample incidents as test data.
